# 모드 포털 웹앱 설계

작성일: 2026-09-18

## 1. 개요

친구들이 **어떤 모드가 적용 중이고, 자기가 무엇을 설치해야 하는지**를 한눈에 보는 페이지와, 방장이 서버와 모드를 제어하는 관리 패널을 만든다.

친구용 페이지는 서버 PC가 꺼져 있어도 열려야 한다.

## 2. 배경

원래 스펙(`2026-09-17-valheim-dedicated-server-design.md`)의 서브프로젝트 C는 **"클라우드 VM을 켜는 버튼"** 이 핵심이었다. 이후 GCP 무료 체험판이 선불 결제를 요구해 집 PC 자가 호스팅으로 전환하면서 그 전제가 사라졌다. 이 문서가 서브프로젝트 C를 대체한다.

현재 운영 상태:

| 항목 | 값 |
|---|---|
| 서버 | 집 PC, WSL2 + Docker, 발헤임 1.0.14 |
| 접속 주소 | 공인 IPv4 (유동), 포트 UDP 2456-2457 |
| 내부 IP | 192.168.219.117 (DHCP 고정 할당됨) |
| 1층 모드 | PlantEverything, ServersideQoL, ServersideQoL_AutoProcess |
| 3층 모드 | 미도입 |
| 저장소 | github.com/firstquator/valheim-multi, `main` 브랜치 |

## 3. 요구사항

### 친구용 페이지
- 서버 PC 상태와 무관하게 항상 열린다
- 현재 적용 모드 목록, 각 모드의 설명과 사용법
- **설치해야 하는 모드와 안 해도 되는 모드를 명확히 구분**
- 설치 가이드
- 접속 주소와 비밀번호 (복사 가능)
- 서버 상태와 현재 접속자

### 관리 패널
- 서버 시작, 중지, 재시작
- 설치된 모드 목록과 업데이트 확인
- 모드 추가, 끄기, 켜기
- 자주 쓰는 설정값 편집
- 백업 목록, 로그 열람

## 4. 아키텍처

배포 단위 3개.

```
[GitHub Pages]  친구용 정적 페이지            24시간 가동
      ↑ 빌드                ↑ fetch (30초)
[저장소 data/]         [GitHub Gist]  상태 JSON
                            ↑ 30초마다 푸시
                       [서버 PC]
                         ├── status-publisher  (상태 수집 및 푸시)
                         └── admin  (localhost 관리 패널)
```

`status-publisher` 가 `admin` 과 분리된 것이 중요하다. 관리 패널을 켜지 않아도 친구들은 서버 상태를 본다.

### 왜 Gist 인가

정적 페이지(HTTPS)가 서버 PC(HTTP)를 직접 호출하면 브라우저가 **혼합 콘텐츠**로 차단한다. 포트를 추가로 열어도 막힌다. 그래서 중계가 필요하다.

| 방식 | 지연 | 추가 계정 | 판정 |
|---|---|---|---|
| **GitHub Gist** | 30초 | 없음 | **채택** |
| Cloudflare Tunnel | 즉시 | 필요 | 나중의 업그레이드 경로 |
| 저장소에 커밋 | 1분 이상 | 없음 | 커밋 히스토리 오염. 제외 |

Gist 는 기존 GitHub 계정을 쓰고, `api.github.com/gists/<id>` 는 CORS 를 허용한다. 갈아탈 때는 프런트엔드의 데이터 출처만 바꾸면 된다.

## 5. 데이터 모델

### 5.1 모드 정보의 정본: `data/mods.json`

친구 페이지도 관리 패널도 이 파일 하나에서 읽는다. 모드를 바꾸면 이 파일을 고치고 커밋하면 사이트가 자동 갱신된다.

```json
{
  "schemaVersion": 1,
  "modpack": {
    "version": "v1",
    "r2modmanCode": null
  },
  "mods": [
    {
      "id": "ServersideQoL_AutoProcess",
      "owner": "ArgusMagnus",
      "version": "2.0.11",
      "tier": 1,
      "name": "자동 제련 공급",
      "summary": "제련소, 가마, 풍차에 근처 상자에서 재료를 자동으로 넣습니다",
      "usage": "제련소 옆에 광석 상자를 두기만 하면 됩니다",
      "thunderstoreUrl": "https://thunderstore.io/c/valheim/p/ArgusMagnus/ServersideQoL_AutoProcess/",
      "warnings": []
    }
  ]
}
```

| 필드 | 의미 |
|---|---|
| `tier` | 1 = 서버 전용(친구 설치 불필요), 2 = 개인 선택, 3 = 전원 설치 필수 |
| `usage` | 친구가 실제로 어떻게 쓰는지. 단축키나 어디에 나타나는지 |
| `warnings` | 충돌 경고 등. 페이지에서 눈에 띄게 표시한다 |

`tier` 값은 1, 2, 3 만 허용한다. 빌드 시 스키마를 검증해 오타를 잡는다.

### 5.2 상태 JSON (Gist 에 저장)

```json
{
  "updatedAt": "2026-09-18T03:45:00Z",
  "server": {
    "running": true,
    "name": "gaybar",
    "playerCount": 3,
    "players": ["누들낑", "모카비비"],
    "gameVersion": "1.0.14",
    "networkVersion": 40,
    "address": "182.230.196.27:2456"
  },
  "backup": {
    "lastAt": "2026-09-18T03:05:00Z",
    "count": 7
  }
}
```

접속자 이름은 `status.json` 이 비워서 주므로 **서버 로그에서 추출**한다. 로그의 `Got character ZDOID from <이름>` 패턴을 쓴다.

## 6. 데이터 흐름

```
30초마다 (status-publisher):
  localhost status.json 조회 ──┐
  docker ps                   ├→ 상태 객체 조립 → Gist PATCH
  최근 로그 파싱               ┘
  백업 디렉터리 확인

친구 브라우저:
  페이지 로드 → mods.json (빌드에 포함) 즉시 렌더
             → Gist API fetch → 상태 영역만 갱신
```

모드 정보는 빌드에 포함되므로 **서버와 무관하게 즉시 보인다.** 상태만 나중에 채워진다. 서버가 꺼져 있어도 페이지가 비어 보이지 않는다.

## 7. 드리프트 감지

선언한 것과 실제로 깔린 것이 어긋날 수 있다. 실제로 겪은 사례가 있다. `ServersideQoL` 이 로그에 "Loading" 으로 뜨는데 패처 DLL 이 없어 config 조차 생성하지 못한 채 기능이 죽어 있었다.

관리 패널이 둘을 비교한다.

| 선언 (`mods.json`) | 실제 (파일시스템 + 로그) | 판정 |
|---|---|---|
| 있음, 버전 일치 | 로드됨, config 있음 | 정상 |
| 있음 | 파일 없음 | 미설치 |
| 있음, 버전 다름 | 로드됨 | 버전 불일치 |
| 없음 | 로드됨 | 유령 모드 |
| 있음 | 로드됨, config 없음 | **초기화 실패** |

마지막 항목이 핵심이다. 로그의 `Loading [...]` 만 보면 정상으로 보이지만 실제로는 죽어 있는 상태를 잡아낸다.

친구 페이지는 **선언된 것**을 보여주고, 관리 패널은 **차이**를 보여준다.

## 8. 친구 페이지 구성

### 탭

| 탭 | 아이콘 | 내용 |
|---|---|---|
| 서버 | `Home01` | 상태, 접속 주소, 비밀번호, 게임 버전, 현재 접속자 |
| 모드 | `PackageOpen` | 설치 불필요 그룹과 설치 필요 그룹 |
| 설치 가이드 | `Download04` | r2modman 단계별 안내 |
| 월드 | `Globe02` | 월드 설정값, 백업 현황 |

> 위 아이콘 이름은 추정값이다. HugeIcons 의 실제 export 이름을 구현 시 확인한다 (U6).

모드 탭 안에서 두 그룹을 **탭으로 더 나누지 않는다.** 친구가 둘을 비교해서 봐야 하기 때문이다. 탭으로 가르면 "설치 필요" 쪽만 보고 나머지도 설치하려 든다.

### 반드시 있어야 하는 것

| 항목 | 이유 |
|---|---|
| 접속 주소와 복사 버튼 | 공인 IP 가 유동이다. 이것이 사실상 DDNS 를 대체한다 |
| 비밀번호와 복사 버튼 | 매번 묻는 것을 없앤다 |
| 게임 버전 | 버전이 다르면 접속 자체가 안 된다. 가장 흔한 문제다 |
| 서버 상태 | 켜짐 또는 꺼짐, 인원, "30초 전 확인" |
| 인벤토리 모드 충돌 경고 | 둘 이상 설치하면 아이템이 소실된다 |

### 두 그룹의 시각적 분리

친구 입장에서 이 페이지의 존재 이유는 "내가 무엇을 해야 하는가" 에 답하는 것이다.

- **설치 불필요 그룹**: 낮은 채도, 체크 아이콘. 넘어가도 된다는 인상
- **설치 필요 그룹**: 악센트 테두리, 행동 버튼. 봐야 한다는 인상

같은 카드 스타일로 나열하면 친구들이 전부 설치하려 든다.

### 경고는 각주가 아니라 블록으로

인벤토리 모드 충돌은 아이템이 사라지는 문제다. 작은 글씨로 적으면 아무도 읽지 않는다. 설치 필요 섹션 맨 위에 눈에 띄는 블록으로 놓는다.

## 9. 관리 패널 구성

| 탭 | 내용 |
|---|---|
| 서버 | 시작, 중지, 재시작, 접속자 현황, 자원 사용량 |
| 모드 | 설치 목록, 드리프트 표시, 업데이트 확인, 추가, 끄기와 켜기 |
| 설정 | 자주 쓰는 설정값 편집, 설정 파일 직접 열기 |
| 백업 | 목록, 폴더 열기 |
| 로그 | 필터링된 로그 열람 |

### 설정 편집의 범위

모드 설정 파일 전체를 UI 로 만들지 않는다. `PlantEverything` 설정만 23KB 에 항목이 수백 개다.

자주 건드리는 것만 노출한다.

- 서버 이름, 비밀번호
- `ExtraSlots` 의 슬롯 켜기와 끄기
- `AutoProcess` 의 동작 반경

그 외는 **설정 파일 직접 열기** 버튼으로 처리한다. 전체 편집기는 필요해지면 그때 만든다.

## 10. 디자인

### 10.1 제약

사용자가 정한 것이며, 이전 스펙의 제약을 일부 대체한다.

| 항목 | 규칙 |
|---|---|
| 이모지 | **한 글자도 쓰지 않는다.** 모든 아이콘은 HugeIcons |
| 사이드 메뉴바 | 기본 접힘, hover 시 부드럽게 펼침 |
| 배치 | 긴 스크롤이 아니라 **탭** |
| 반응형 | 데스크톱 기준. 태블릿 가로까지 깨지지 않게. 모바일 최적화는 제외 |
| em dash, en dash | 문서와 UI 문구에서 사용 금지 |

> 이전 스펙에는 "좌측 사이드바 금지" 와 "상단 띠 금지" 가 있었다. 사용자가 2026-09-18 에 사이드 메뉴바를 요청해 그 제약을 대체한다. 상단 띠 금지는 유지한다.

### 10.2 레이아웃

```
접힌 상태 (64px)                    hover 상태 (240px)
┌────┬────────────────────┐        ┌──────────────┬──────────┐
│[1] │  gaybar            │        │ [1] 서버      │  gaybar  │
│[2] │  접속 중 · 3명      │        │ [2] 모드      │          │
│[3] │  ┌──────────────┐  │  hover │ [3] 설치 가이드│  ┌────┐  │
│[4] │  │ 주소  [복사] │  │  ────> │ [4] 월드      │  │    │  │
│    │  │ 비번  [복사] │  │        │              │  │    │  │
└────┴────────────────────┘        └──────────────┴──────────┘

[1]~[4] 는 HugeIcons 아이콘 자리다. 사이드바는 콘텐츠 위에 얹히고
콘텐츠를 밀지 않는다.
```

접힌 상태는 아이콘만 64px. hover 하면 240px 로 펼쳐지며 라벨이 페이드인된다. **사이드바는 콘텐츠 위에 얹히고 콘텐츠를 밀지 않는다.** 레이아웃이 출렁이면 안 된다.

```css
transition: width 220ms cubic-bezier(0.32, 0.72, 0, 1);
```

라벨은 폭 전환보다 60ms 늦게 나타난다. 동시에 움직이면 글자가 찌그러져 보인다.

### 10.3 색

양피지 텍스처와 룬 폰트는 쓰지 않는다. 팬사이트처럼 보인다. 게임의 실제 색감에서 가져오되 **채도를 낮게** 잡는다.

| 토큰 | 값 | 출처 |
|---|---|---|
| `--bg` | `#16181C` | 밤의 숲 |
| `--surface` | `#1E2126` | |
| `--accent` | `#C8955A` | 대장간 불빛, 가죽 |
| `--highlight` | `#D9A441` | 화톳불 |
| `--success` | `#7A9A6B` | 이끼 |
| `--warning` | `#C4634A` | 녹슨 철 |

질감은 텍스처 대신 아주 미세한 노이즈 오버레이(불투명도 2~3%)로 준다.

다크 모드만 만든다. 게임 서버 페이지이고 주로 밤에 본다. 라이트 모드는 토큰만 추가하면 되므로 필요해지면 그때 만든다.

### 10.4 폰트

| 용도 | 폰트 |
|---|---|
| 본문과 UI | **Pretendard Variable** |
| 제목 | Pretendard, weight 700, 자간 -0.02em |
| 주소, 버전, 코드 | **JetBrains Mono** |

별도 디스플레이 폰트를 섞지 않는다. 한국어에서 장식적인 제목 폰트는 본문과 이질감을 만들고 가독성을 떨어뜨린다. 무게와 자간으로 위계를 만든다.

주소와 버전을 모노스페이스로 쓰는 것은 **복사해서 붙여넣을 값이라는 신호**를 주기 위해서다.

### 10.5 아이콘

`@hugeicons/core-free-icons` 의 **stroke-rounded** 계열로 통일한다. 선 굵기 1.5px, 크기 20px(인라인) 또는 24px(사이드바).

친구 페이지는 정적이므로 React 를 싣지 않는다. `@hugeicons/static` 의 SVG 를 **빌드 타임에 인라인**한다. 런타임 JS 없이 아이콘이 나온다.

> 사용자가 제시한 `hugeicons-react` 는 폐기된 패키지다. `@hugeicons/react` 가 현행이며, 확인 결과 관련 패키지는 모두 MIT 라이선스다.

### 10.6 반응형

| 폭 | 동작 |
|---|---|
| 1280px 이상 | 콘텐츠 최대 960px, 중앙 정렬 |
| 1024 ~ 1280px | 콘텐츠 유동 |
| 768 ~ 1024px | 사이드바 고정 축소, 카드 2열에서 1열로 |
| 768px 미만 | 최소한 읽히기만 한다. 최적화하지 않는다 |

## 11. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 친구 페이지 | **Astro** | 콘텐츠 중심 정적 사이트에 적합. 기본 JS 0, 상태 영역만 인터랙티브 |
| 스타일 | **바닐라 CSS + 디자인 토큰** | 프레임워크 기본값 인상을 피한다. 이 규모에 토큰 몇 개면 충분 |
| 관리 패널 | **Node + Hono** | 가볍고 docker 명령 실행에 충분 |
| 상태 퍼블리셔 | Node 단일 스크립트 | 의존성 최소 |
| 배포 | GitHub Actions to Pages | 커밋하면 자동 배포 |

## 12. 에러 처리

| 상황 | 동작 |
|---|---|
| Gist fetch 실패 | 모드 정보는 그대로, 상태 영역만 "확인 불가" |
| 상태가 3분 이상 낡음 | **서버 꺼짐으로 표시.** 낡은 데이터를 현재인 척하지 않는다 |
| PC 가 꺼짐 | 위와 동일. 자연스럽게 꺼짐으로 수렴한다 |
| Gist 토큰 만료 | 퍼블리셔가 로그에 남기고 재시도. 페이지는 3분 뒤 꺼짐 표시 |
| 관리 패널의 docker 명령 실패 | **stderr 원문을 노출한다.** "알 수 없는 오류" 는 디버깅을 막는다 |
| `mods.json` 스키마 위반 | 빌드 실패. 잘못된 정보가 배포되지 않게 한다 |

## 13. 테스트

| 대상 | 방법 |
|---|---|
| `data/mods.json` | 스키마 검증. 필드 누락, `tier` 범위, 중복 `id` |
| 상태 조립 로직 | 기존 `tests/fixtures/status-*.json` 4종 재사용 |
| 로그 파서 | 접속과 퇴장 로그 픽스처로 캐릭터 이름 추출 검증 |
| 드리프트 감지 | 선언과 실제의 조합별 판정 (표 7절의 5가지) |
| 관리 패널 | docker 호출을 목킹. 명령 구성과 에러 전파 검증 |
| 시각 | 실물 확인. 사이드바 hover 전환, 탭 전환, 태블릿 폭 |

## 14. 리스크

| # | 리스크 | 완화 |
|---|---|---|
| R1 | Gist API 의 CORS 나 캐시 동작이 기대와 다름 | 구현 초기에 실측한다. 실패 시 Cloudflare Tunnel 로 전환 |
| R2 | 상태에 공인 IP 가 들어가므로 Gist 가 공개되면 서버 주소가 노출됨 | 비밀번호는 Gist 에 넣지 않는다. 주소 노출은 감수한다(서버가 이미 public 등록 상태) |
| R3 | 로그 파싱이 발헤임 업데이트로 깨짐 | 파서 실패 시 접속자 이름만 비우고 인원 수는 유지 |
| R4 | 모드가 늘면 `mods.json` 수기 관리가 번거로움 | 관리 패널이 설치 결과로 초안을 생성하도록 확장 |
| R5 | 관리 패널이 localhost 전용이라 방화벽이나 포트 충돌 가능 | 포트를 설정 가능하게 한다 |
