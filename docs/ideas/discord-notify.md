# 디스코드 알림 (아직 만들지 않음)

2026-09-20 에 "이것부터 만들자" 후보로 올라왔다가 **기록만 남기기로**
정했다. 여기 적어 두는 이유는 나중에 다시 논의할 때 같은 이야기를
처음부터 하지 않기 위해서다.

## 왜 값이 있다고 봤나

친구들이 포털을 계속 띄워 두지 않는다. 지금 구조에서는 서버가 켜졌는지,
모드팩이 바뀌었는지를 알려면 **사람이 먼저 사이트를 열어야 한다.**
알림은 그 방향을 뒤집는다. 실사용 빈도로 따지면 지금까지 만든 어떤
화면보다 많이 쓰일 가능성이 크다.

## 붙일 자리

`agent/status-publisher.mjs` 의 `tick()` 안이다. 이미 30초마다

- 컨테이너가 도는지 (`containerRunning`)
- 누가 접속해 있는지 (`parsePlayers` -> `payload.server.players`)

를 알고 있으므로, **상태가 바뀐 순간만 골라내면** 된다. 새 수집이
필요 없다.

## 보낼 만한 사건

| 사건 | 판정 방법 |
| --- | --- |
| 서버가 켜짐 / 꺼짐 | `payload.server.running` 이 직전 tick 과 달라질 때 |
| 아무도 없다가 누가 들어옴 | `players.length` 가 0 에서 1 이상이 될 때 |
| 다 나가서 비었음 | 1 이상에서 0 이 될 때 |
| 모드팩이 갱신됨 | `data/mods.json` 의 `modpack.changes` 맨 앞 날짜가 바뀔 때. 이건 배포 쪽(GitHub Actions)에서 보내는 편이 맞다 |

접속할 때마다 보내면 안 된다. 한 사람이 재접속을 반복하면 채널이
도배된다. **0 에서 1 로 넘어가는 순간만** 보내는 것이 요점이다.

## 걸림돌

- **웹훅 URL 이 비밀이다.** 저장소에 넣으면 안 된다. `GIST_TOKEN` 과
  같은 방식으로 환경변수(`DISCORD_WEBHOOK`)로 받아야 한다.
  `agent/env.example` 에 이름만 적어 둔다.
- **이 저장소는 공개다.** 채널 이름이나 서버 초대 링크를 코드나 문서에
  적지 않는다.
- **알림이 시끄러우면 껐다가 다시 안 켠다.** 처음에는 서버 켜짐/꺼짐
  둘만 보내고, 부족하다는 말이 나오면 늘린다.
- **status-publisher 가 죽으면 알림도 죽는다.** 지금도 연속 실패
  20 회면 프로세스를 끝내고 상위 매니저가 살리는 구조라 그대로 따른다.
  알림 실패가 상태 푸시를 막아서는 안 된다. try/catch 로 가둔다.

## 만들 때

`agent/lib/notify.mjs` 를 순수 함수로 둔다. "직전 상태와 지금 상태를
받아 보낼 메시지 목록을 돌려주는" 모양이면 `tests/notify.test.mjs` 로
전부 시험할 수 있다. 실제 전송(fetch)은 status-publisher 가 맡는다.
`collect.mjs` 와 `logparse.mjs` 가 그렇게 나뉘어 있으니 같은 결을 따른다.
